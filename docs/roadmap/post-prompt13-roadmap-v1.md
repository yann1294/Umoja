# Post-Prompt-13 Roadmap v1

Status: planned; no operational domain in this roadmap is implemented by the public-site review

Every prompt below uses Supabase only, additive migrations, explicit grants and RLS matrices,
application AES-256-GCM/HMAC boundaries, quarantined private files until real malware scanning,
English/French parity, the responsive viewport matrix, accessibility checks, and genuine 200%
browser zoom. Technical completion is recorded separately from private-preview and production
readiness. None may add finance transfers, public bidding, opaque scoring, or unapproved legal
assumptions.

## Prompt 14 - Organizations and opportunity qualification

Depends on the accepted profile/membership foundation. Add verified organizations, scoped
organization membership, opportunity intake linkage, qualification history, explicit originating
and representing organizations, and auditable human decisions. Acceptance requires cross-tenant
denial, no ownership inference from applicant input, an EN/FR qualification UI, and complete cleanup.

## Prompt 15 - Feasibility and versioned acceptance

Depends on Prompt 14. Add evidence-based feasibility reviews, clarification/decline/referral states,
approval authority, and a versioned statement of work. Intake review must remain distinct from
commercial/project acceptance. Acceptance requires controlled concurrent decisions, immutable
history, and no single-checkbox acceptance.

## Prompt 16 - Projects, modules, and least-context membership

Depends on Prompt 15. Add accepted projects, hierarchical modules, dependencies, scoped project
membership, confidentiality classes, inputs, outputs, and acceptance criteria. Acceptance requires
Core access only on active projects and Extended access only to assigned modules plus explicit
dependency outputs.

## Prompt 17 - Staffing and assignment confirmation

Depends on Prompt 16 and existing availability. Add evidence-based shortlists, allocation conflict
checks, assignment offers, human confirmation, expiry, and withdrawal. Never expose private rates,
HR data, or an opaque talent score. Acceptance requires safe competing assignments and overbooking
prevention.

## Prompt 18 - Milestones, deliverables, documentation, and review

Depends on Prompts 16-17. Add versioned milestones, module deliverables, quarantined files,
documentation, review, changes requested, acceptance, and dependency release. Acceptance requires
no milestone closure without accepted deliverables and useful documentation.

## Prompt 19 - Notifications, activity, and operational audit

Depends on Prompts 14-18. Add in-product notification preferences, delivery state, scoped activity
feeds, digest-only audits, expiry reminders, and safe recovery states. Email remains disabled until
the approved SMTP and inbox gates pass; logs must remain redacted.

## Prompt 20 - Extended-to-Core assessment and progression

Depends on delivery evidence from Prompt 18. Add versioned rubrics, visible criteria, review packets,
growth plans, appeal state, separation of duties, and membership history. Acceptance forbids hidden
scores and requires the contributor to see applicable criteria and evidence.

## Prompt 21 - AfricIT workflows

Depends on Prompt 19 and the CMS foundation. Add reviewed workshops, sessions, registrations,
resources, research states, authorship, accessibility, consent, and publication status. AfricIT
remains a Umoja capability programme, not a competing master brand.

## Prompt 22 - Historical project import and case-study consent

Depends on Prompt 14 organizations and Prompt 18 delivery records. Add a private, reversible import
pipeline for unverified historical projects, deduplication, relationship/outcome normalization,
consent evidence, redaction, editorial review, and withdrawal. Nothing reaches `/work` without
verified public fields and client/contributor publication approval.

## Prompt 23 - Record-only contribution ledger

Depends on approved Prompt 15 contract/SOW versions and Prompt 18 acceptance evidence. Behind legal
and feature gates, record proposed contribution bases, currencies, policy versions, evidence,
approvals, corrections, and immutable audit history. Do not deduct, hold, transfer, escrow, invoice,
or pay funds. Production remains blocked until the legal/accounting model is approved.
